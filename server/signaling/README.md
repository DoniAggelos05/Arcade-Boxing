Signaling server

Ο signaling server φέρνει τους παίκτες σε επαφή.Διαχειρίζεται τα lobbies και προωθεί τα μηνύματα που χρειάζονταιγια να συνδεθούν οι παίκτες μεταξύ τους με WebRTC.
Τον ίδιο τον αγώνα δεν τον βλέπει περνάει peer-to-peer.

Είναι γραμμένος σε Node.js με τη βιβλιοθήκη "ws":WebSocket και ακούει στη θύρα 8443.
Το παιχνίδι συνδέεται μέσω του NetworkManager(δες το README του src/Network για περισσότερες πληροφορίες).


Αρχεία

-"server.js":ο WebSocket server.Δέχεται συνδέσεις,ελέγχει κάθε μήνυμα και το δίνει στον σωστό handler
-"handlers.js":μία συνάρτηση για κάθε τύπο μηνύματος(create_lobby,join,kick κλπ)
-"lobby.js":η κλάση "Lobby"(παίκτες,host,broadcast)
-"lobbyManager.js":κρατάει όλα τα lobbies,φτιάχνει κωδικούς και τη δημόσια λίστα
-"turn.js":φτιάχνει τα προσωρινά credentials για τον TURN server
-"logger.js":γραμμές log με επίπεδο σοβαρότητας
-"config.js":οι ρυθμίσεις(θύρα,όρια,TURN)


Σύνδεση παίκτη(server.js)

Μόλις συνδεθεί ένας παίκτης ο server του στέλνει "welcome" μαζί με τα στοιχεία STUN/TURN.
Κάθε μήνυμα που έρχεται περνάει από αυτούς τους ελέγχους πριν φτάσει σε handler:

-το πολύ 30 μηνύματα το δευτερόλεπτο ανά σύνδεση,αλλιώς η σύνδεση κλείνει
-το πολύ 64 KB ανά μήνυμα("maxPayload")
-πρέπει να είναι έγκυρο JSON με πεδίο "type"
-το "type" πρέπει να είναι δικός μας handler("Object.hasOwn",ώστε να μη γίνεται να καλέσει κανείς
κρυφές μεθόδους της JavaScript όπως "toString")

Αν ένας handler πετάξει σφάλμα γράφεται στο log και ο server συνεχίζει να τρέχει.

Κάθε 30 δευτερόλεπτα ο server στέλνει ping σε όλους.Όποιος δεν απάντησε στο προηγούμενο ping αποσυνδέεται.
Όταν κλείνει μια σύνδεση ο παίκτης βγαίνει αυτόματα από το lobby του.


Μηνύματα(handlers.js)

Από τον παίκτη προς τον server:

-"list_lobbies":ζητάει τα δημόσια lobbies->απάντηση "lobbies"
-"create_lobby":φτιάχνει lobby,ο παίκτης γίνεται host με id 1-> απάντηση "lobby_created"
-"join":μπαίνει σε lobby με κωδικό-> απάντηση "joined" με τους υπόλοιπους παίκτες,και στους άλλους "peer_joined"
-"leave":φεύγει από το lobby.Αν φύγει ο host το lobby κλείνει και όλοι παίρνουν "lobby_closed"
-"kick":ο host διώχνει παίκτη-> ο παίκτης παίρνει "kicked" και οι άλλοι "peer_left"
-"set_locked":ο host κλειδώνει ή ξεκλειδώνει το lobby-> όλοι παίρνουν "lock_changed"
-"start_match":ο host ξεκινάει τον αγώνα και στέλνει τη σειρά των παικτών ("roster")-> όλοι παίρνουν "match_started" με το ίδιο "roster"
-"signal":προωθεί ένα μήνυμα WebRTC(offer,answer,ICE) σε άλλον παίκτη του ίδιου lobby

Σε κάθε απόρριψη ο server στέλνει "error" με τον λόγο(πχ"lobby_full","no_such_lobby","not_host").

Κανόνες που ελέγχει ο server και όχι ο client:
-μόνο ο host(id 1) μπορεί να κάνει kick,κλείδωμα και έναρξη αγώνα
-σε κλειδωμένο lobby μπαίνει κανείς μόνο με κωδικό και όχι από τη λίστα("fromList")
-σε γεμάτο lobby ή lobby που ξεκίνησε δεν μπαίνει κανείς
-τα ονόματα κόβονται στους 20 χαρακτήρες.
Αν είναι κενά παίρνουν τυχαίο όνομα("Player#1234")


Lobbies(lobby.js/lobbyManager.js)

Κάθε lobby έχει κωδικό 6 χαρακτήρων(τυχαίο από "crypto"),όνομα,μέγιστους παίκτες(2 έως 10) και ένα Map
με τους παίκτες({ id:σύνδεση }).Ο host έχει πάντα id 1 και οι επόμενοι 2,3,4...

-"broadcast(msg,exceptId)":στέλνει ένα μήνυμα σε όλους τους παίκτες του lobby εκτός από έναν(τον broadcaster)
-"otherPlayers(id)":οι υπόλοιποι παίκτες,για να τους δει όποιος μόλις μπήκε
-"listPubLobbies()":μόνο όσα δεν είναι κλειδωμένα και δεν έχουν ξεκινήσει


TURN credentials(turn.js)

Δεν υπάρχουν σταθεροί κωδικοί για τον TURN server.Για κάθε παίκτη:
    username = η ώρα που λήγει(τώρα + 1 ώρα)
    password = HMAC-SHA1(secret,username) σε base64

Το secret το ξέρουν μόνο ο signaling και ο coturn.Ο coturn ξαναϋπολογίζει το ίδιο HMAC για να ελέγξει τον κωδικό και απορρίπτει όσους έχουν λήξει 
οπότε δεν χρειάζεται βάση δεδομένων με χρήστες.


Log(logger.js)

Κάθε γραμμή έχει επίπεδο,IP,lobby και τύπο μηνύματος:
-"SAFE":όλα κανονικά
-"INFO":απορρίφθηκε για αθώο λόγο(λάθος κωδικός,γεμάτο lobby)
-"SUSPICIOUS":σωστή μορφή αλλά το παιχνίδι μας δεν θα το έστελνε ποτέ
-"WARNING":δεν μοιάζει καν με μήνυμα
-"ERROR":σφάλμα στον δικό μας κώδικα

Ότι έρχεται από τον παίκτη καθαρίζεται πριν γραφτεί(μόνο απλοί χαρακτήρες έως 40) ώστε να μη μπορεί κανείς να γράψει ψεύτικες γραμμές στο log.


Ρυθμίσεις(config.js)

Διαβάζονται από μεταβλητές περιβάλλοντος που τις δίνει το systemd(δες το README του server/nixos):
-"PORT":η θύρα του server(8443)
-"PUBLIC_HOST":η διεύθυνση του TURN server που δίνεται στους παίκτες
-"TURN_SECRET_FILE":πού βρίσκεται το secret του TURN


Εκτέλεση

Στον server τρέχει ως υπηρεσία systemd.Αφού αλλάξει ο κώδικας εδώ:
    npm install
    signaling-deploy

Το "signaling-deploy" αντιγράφει τον κώδικα στο "/srv/signaling" και κάνει restart την υπηρεσία.
Τα logs φαίνονται με:
    journalctl -u signaling -f

(Διευρκίνιση:
    Ο server πρέπει να είναι προσβάσιμος από το internet:
    -δημόσια IP (όχι πίσω από CGNAT)
    -ανοιχτή η θύρα 8443 TCP στο firewall και port forward στον router
    Αλλιώς οι παίκτες εκτός τοπικού δικτύου δεν μπορούν να συνδεθούν
    (δες το README του server/nixos για περισσότερες πληροφορίες))
